## 复杂度分析

### ★☆☆☆☆ 简单（3 项）

#### 1. 右键删除文档报错（缺陷）

- **现象**：右侧面板文件树右键删除文档时报错
- **排查方向**：前端右键菜单 handler → IPC 调用 → Worker 文件删除逻辑，定位报错点
- **修复方式**：大概率是 IPC 参数/路径问题或删除逻辑缺少边界处理
- **涉及层**：前端 + Worker（FileTools）
- **预估**：0.5~1 天（需先复现定位）

#### 2. 查看/编辑同文件去重合并

- **现象**：聊天窗折叠统计中，同一文件被多次查看或编辑时未合并，统计重复
- **修复方式**：折叠块摘要按文件路径去重，合并计数
- **涉及层**：前端（process-summary.ts / ExecutionProcessBlock）
- **预估**：0.5 天

#### 3. "更改工作文件夹"改为"打开工作文件夹"

- **现象**：左侧项目列表的"更改工作文件夹"按钮语义不准确，应改为打开系统文件管理器
- **修复方式**：改 IPC 调用为 `shell.openPath` / `shell.showItemInFolder`，文案改为"打开工作文件夹"
- **涉及层**：前端 + Main 进程（shell API）
- **预估**：0.5 天

### ★★☆☆☆ 中等（2 项）

#### 4. 底部统计状态移到输入框内部左上角

- **现象**：底部统计板块的"状态显示"干扰输入，需移到输入框内部左上角
- **改动**：调整 InputArea 布局，状态指示器从底部移到输入框内左上角浮动/内嵌
- **涉及层**：前端（InputArea / ComposerRuntimeStatus）
- **注意**：需考虑输入框高度自适应、状态不遮挡输入内容
- **预估**：0.5~1 天

#### 5. 右侧面板显示隐藏文件

- **现象**：右侧面板文件树加载时略过 `.` 开头的隐藏文件，需显示
- **改动**：文件树加载逻辑去掉 `.` 前缀过滤，或加"显示隐藏文件"开关
- **涉及层**：前端（AgentFilesPanel / 文件树加载逻辑）
- **预估**：0.5 天

### ★★★☆☆ 中高（1 项）

#### 6. 右侧面板文件树搜索、刷新按钮

- **现象**：右侧面板文件树缺少搜索和刷新操作按钮
- **改动**：
  - 搜索：文件树顶部加搜索框，按文件名模糊过滤
  - 刷新：加刷新按钮重新加载文件树
- **涉及层**：前端（AgentFilesPanel + 文件树组件）
- **预估**：1~2 天

### ★★★★★ 复杂（1 项）

#### 7. Goal 编排记录可视化

- **现象**：Goal 自动编排过程不可见，用户无法查看每轮计划及执行详情
- **改动**：
  - 新建 `goal_orchestrations` + `goal_plan_tasks` 表（持久化编排记录）
  - GoalOrchestrator 执行过程中写入编排记录（每轮 plan + 执行结果）
  - 前端 Goal 右侧面板展示编排记录（计划列表 + 每轮执行详情）
- **涉及层**：Infrastructure（DB 建表）+ Agent（GoalOrchestrator 写入）+ 前端（新面板组件）
- **预估**：3~5 天

## 推荐迭代范围

### 方案 A：纯简单需求打包（快速出活）

**范围**：#1 + #2 + #3 + #4 + #5 + #6（排除 #7）

- 全部是 UI 层修复和改进，不涉及 DB 和后端架构
- 工作量：3~5 天
- 风险低，验证简单
- 适合快速迭代，提升日常使用体验

### 方案 B：简单需求 + Goal 可视化（完整迭代）

**范围**：#1 ~ #7 全部

- 包含 Goal 编排记录可视化（#7），需要 DB 建表 + 后端记录 + 前端面板
- 工作量：6~10 天
- 需拆分为多个 Plan
- 适合作为一个完整迭代

### 方案 C：只做文件树相关（聚焦右侧面板）

**范围**：#1 + #5 + #6

- 聚焦右侧面板文件树的三个问题：删除报错 + 隐藏文件 + 搜索刷新
- 工作量：2~3 天
- 适合快速修复右侧面板的集中问题
